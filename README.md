# RAG From Scratch

A minimal, readable Retrieval-Augmented Generation (RAG) pipeline in plain Python — no LangChain, no LlamaIndex. Every stage (load → chunk → embed → index → retrieve → generate) lives in its own small file so you can see exactly how RAG works.

It runs fully locally: embeddings come from `sentence-transformers`, vectors are stored in FAISS, and answers are generated by any OpenAI-compatible LLM (Ollama by default). A small web UI, **RAG Explorer**, shows the answer alongside the retrieved chunks and their similarity scores.

> New to RAG? Read [TUTORIAL.md](TUTORIAL.md). It walks through each stage and explains the reasoning behind it.

## How it works

```
 PREPARATION (once, at startup)                QUERY TIME (every question)

 data/*.txt                                     question
     │                                              │
 1. LOAD     loader.py      → {text, source}        │ embed
 2. CHUNK    chunker.py     → 100-word pieces,      ▼
                              20-word overlap   5. RETRIEVE  retriever.py
 3. EMBED    embeddings.py  → 384-dim vectors       │  top-k closest chunks
 4. INDEX    vector_store.py→ FAISS inner-product   ▼
                              index             6. GENERATE  rag.py
                                                    question + chunks → LLM
                                                    → answer with sources
```

- **Embeddings:** `all-MiniLM-L6-v2`, normalized so inner product equals cosine similarity.
- **Vector store:** `faiss.IndexFlatIP`, an exact search index. That's plenty for small corpora.
- **Grounded answers:** the prompt tells the model to answer only from the retrieved context, cite source filenames, and say "I don't know" when the answer isn't there.

## Project structure

```
.
├── app.py               # FastAPI server + API endpoints
├── run.py               # CLI demo: asks a few sample questions
├── static/index.html    # RAG Explorer web UI
├── src/
│   ├── loader.py        # Stage 1: read .txt files, keep the source filename
│   ├── chunker.py       # Stage 2: overlapping word-window chunking
│   ├── embeddings.py    # Stage 3: sentence-transformers embeddings
│   ├── vector_store.py  # Stage 4: FAISS index + chunk metadata
│   ├── retriever.py     # Stage 5: builds the index, runs top-k search
│   └── rag.py           # Stage 6: prompt + LLM call
├── data/                # Your documents (.txt)
├── test_stage4.py       # Sanity check for the vector store
├── test_retriever.py    # Sanity check for retrieval scores
└── TUTORIAL.md          # Step-by-step explanation
```

## Getting started

### 1. Install

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install fastapi uvicorn   # for the web UI
```

### 2. Start a local LLM (Ollama)

```bash
ollama serve
ollama pull llama3.2
```

### 3. Add documents

Put `.txt` files in `data/`. Three sample files (Python, FastAPI, PostgreSQL) are included.

### 4. Run

**Web UI:**

```bash
uvicorn app:app --reload
```

Then open http://localhost:8000.

**CLI:**

```bash
python run.py
```

**Retrieval only (no LLM needed):**

```bash
python test_retriever.py
```

## Configuration

Settings are read from environment variables or a `.env` file:

| Variable         | Default                     | Description                          |
|------------------|-----------------------------|--------------------------------------|
| `LLM_BASE_URL`   | `http://localhost:11434/v1` | Any OpenAI-compatible endpoint       |
| `LLM_MODEL`      | `llama3.2`                  | Model name                           |
| `OPENAI_API_KEY` | `ollama`                    | API key (Ollama ignores it)          |

To use OpenAI instead of Ollama:

```env
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
OPENAI_API_KEY=sk-...
```

## API

| Method | Path        | Body                              | Returns                        |
|--------|-------------|-----------------------------------|--------------------------------|
| `GET`  | `/`         | –                                 | RAG Explorer UI                |
| `POST` | `/ask`      | `{"question": "...", "top_k": 3}` | `{answer, chunks}`             |
| `POST` | `/retrieve` | `{"question": "...", "top_k": 3}` | `{chunks}`. Doesn't call the LLM. |

```bash
curl -X POST localhost:8000/ask \
  -H 'Content-Type: application/json' \
  -d '{"question": "What database can store embeddings?"}'
```

## Limitations

These are deliberate, to keep the code easy to learn from:

- The index is rebuilt in memory on every startup and isn't saved to disk.
- Only `.txt` files are loaded.
- Chunking is by word count, not by sentence or token.
- Search is exact (flat index), with no reranking or hybrid keyword search.

These would be the natural next steps for a production system.
